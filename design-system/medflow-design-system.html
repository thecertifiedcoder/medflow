01 / Design philosophy

Clarity is a clinical tool.

The interface should feel calm for a patient in an unfamiliar environment and precise for a staff member moving through a busy intake queue.

The design avoids alarmist AI presentation, decorative dashboard clutter and colour-only meaning.
01

Patient words first

Preserve the patient's confirmed narrative. Structured output never replaces the original account.

02

Voice with an escape hatch

Voice and typing are equally visible. Permission or transcription failure never blocks typed intake.

03

Evidence before interpretation

Each extracted fact points back to a source phrase. Missing information remains explicitly unknown.

04

Human owns the workflow

AI drafts. Authorised staff review, correct, assign workflow priority and record the next action.

06 / States + resilience

A clear state is part of the interface.

The experience must remain understandable when a microphone is unavailable, AI fails, the network drops or the queue is empty.

Never display a false live state. Never hide a saved intake because a downstream service failed.

Voice permission denied

Microphone access is offYou can enable microphone permission in your browser settings, or type your concern instead.

Keep typed intake available without making the user repeat the form.

Transcription unavailable

We couldn't create a transcriptTry again, record a shorter statement or type your concern.

Do not treat an empty transcript as patient confirmation.

AI extraction failed

AI summary unavailableThe original patient statement is still available for staff review.

AI failure must not block or hide an already-saved intake.

Queue empty

No new intakesNew submissions will appear here.

Do not show fabricated queue metrics as real activity.

Reconnecting

Connection interruptedShowing the last received records. Live updates are paused.

Make freshness and connection state explicit.

Unauthorised staff action

Action not permittedYour account does not have access to change this record.

Enforce permissions in the trusted data layer, not only in the UI.

07 / Implementation handoff

A reference, not a running hospital system.

This HTML file is the visual source of truth for the hackathon prototype. The production app must implement the approved PRD, UX, data contract and safety rules separately.

Visual authority
Use these tokens consistently

Do not introduce new colours, radii, shadows or typography without updating this reference and the token file.

Behaviour authority
Follow the UX specification

The HTML demonstrates visual states. Product routes, validation, permissions and business behaviour are defined in the Markdown specifications.

Safety boundary
AI never owns clinical decisions

Keep original patient wording visible. Label AI content as a draft. Staff owns workflow priority and patient-care decisions.
