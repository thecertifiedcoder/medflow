Design system reference · v1.0

MedFlow

Context-Aware Clinical Intake Engine

A triage nurse copilot, not an AI doctor. This file is the source of truth for MedFlow's visual and interaction language: tokens, components, the patient intake node and the medical command dashboard.

01

Design philosophy

Calm under pressure. Clear when it matters. MedFlow should read as a dependable clinical instrument: structured, restrained and honest about what it knows and who decided it.

The product in one sentence

AI-assisted

Identifies. Never decides. Gemini turns a patient's words into a summary, a symptom list and warning signs for the nurse to review. It never produces a score or a priority.

Calculated

Calculates. Never guesses. A deterministic JavaScript function scores adult TEWS from nurse-entered observations. The same inputs always give the same output.

Nurse-entered

Decides. Always recorded. The nurse enters observations and may override priority with a reason. Every override is written to an audit trail.

Three characteristics, balanced

Clinical authority

Confidence from structure, precision, consistency and restraint. One accent colour. Emergency colours reserved for emergency meaning.

Human warmth

Patients feel understood: plain words, large targets, no jargon. Nurses feel supported, not buried in one more complicated tool.

Operational clarity

Important information is distinguishable at a glance. The next sensible action is always visually obvious.

Personality

MedFlow isDependable · Precise · Calm · Intelligent · Human · Modern · Clinically serious · Operationally efficient
MedFlow is notPlayful · Cartoonish · Decorative · Futuristic for effect · Visually noisy · Over-animated · Gradient-heavy · A chatbot · A wellness app · A fintech dashboard in hospital colours

Eight foundations and how MedFlow adapts them Nielsen Norman Group heuristics, WCAG 2.2 AA, GOV.UK error patterns

PrincipleHow it shows up in MedFlow
1 · Recognition over recallThe original complaint, AI summary, vitals and result sit in one workspace. Queue rows carry ID, age, sex, arrival time, complaint and status so no one memorises across screens. Critical actions always have text labels.
2 · Visibility of system statusA permanent connection chip (Connected · Updating · Reconnecting · Unavailable). Gemini processing, "AI unavailable", vitals saved, score calculated and override recorded each have a visible, announced state.
3 · Error preventionClosed sets use segmented controls, not typing. Units are always visible. Each vital shows its live sub-score. Implausible values ask for confirmation. Overrides need a reason and an explicit confirm.
4 · Hierarchy under loadScan order is fixed: immediate (RED) → AI warnings awaiting review → awaiting triage → triaged → routine information. Weight, rails and bands follow that order; everything else is quiet.
5 · Progressive disclosureThe queue is an overview. Selecting a patient opens the full clinical workspace. Audit history is collapsed until needed.
6 · ConsistencyOne badge, one rail, one source tag, one banner pattern. Same class, same look, same behaviour on every screen. Tokens only; no one-off values.
7 · Human controlEvery important signal carries a source tag: patient's words, AI-generated, calculated, nurse-entered. The interface never claims more authority than it has.
8 · Minimal frictionOne tap per closed choice, numeric keypads for numbers, sensible defaults, short paths. Motion never delays a clinical action.

Non-negotiable product guardrails, and where the interface enforces them

  1. Not an AI doctor. No diagnoses, no treatment advice, no prescriptions anywhere. The AI panel always says "for nurse review, not a diagnosis".
  2. Gemini never scores. The TEWS panel is tagged Calculated; AI panels are tagged AI-generated. They never share a container.
  3. AI warning ≠ SATS RED. Warning: dashed outline + AI tag + alert icon. RED: solid fill + octagon + label. Never interchangeable (see §07, AI red-flag).
  4. Original complaint always visible. It is the first panel in the detail workspace, in the patient's words.
  5. AI failure ≠ submission failure. The patient sees success. The nurse sees an "AI unavailable" chip beside the original complaint.
  6. No silent score. Missing observations show "TEWS not calculated" with the count of missing items. A score appears only when all seven inputs exist.
  7. Overrides have reasons and a trail. The dialog blocks confirmation until a reason is chosen; the audit log records who, what, why and the resulting priority.
  8. No invented content. No pediatric scoring, billing, EHR, statistics, partnerships or performance claims. Firestore collection names are deliberately absent from the design.

Brand foundations

The identity is the Clinical Signal Environment: unstructured human narrative becomes structured information, then clinical assessment, then a prioritised flow. It appears as a mark, a divider, a queue rail and a source system, kept restrained and never literal everywhere.

Concept
A rounded square holding one line. It starts irregular (how patients describe symptoms), settles into a straight line (structure) and ends at a solid node (a decision point for a human). Weight 2.6 on a 40 unit grid, round caps and joins.

Don't
Don't add a cross, stethoscope or heart; don't animate the mark; don't recolour the line with clinical colours.

Rule 1
Never colour alone. Every class carries a text label, a shape (octagon, diamond, square, circle) and, in the queue, a score. Red and green solids have near-identical luminance, so shape and label are what separate them for colour-blind users.
Rule 2
Edge is mandatory on badges, glyphs and rails. Yellow fills reach only 1.6:1 against white and orange 3.3:1, so a dark edge (≥6:1) carries the 3:1 non-text boundary.
Rule 3
Reserved. Red, orange and yellow are used only for clinical meaning and alerts. Never as decorative accents or button colours (destructive button excepted, and it is never beside a triage badge).
Source
Scores, thresholds, labels and time targets are exactly as supplied in the product specification (adult TEWS). They require clinical verification before real-world use. No pediatric scoring exists in this system.

AI red-flag warning vs SATS RED

An AI-identified red flag is a concern needing human review. SATS RED is a calculated classification. They must never be mistaken for each other, so they differ in shape, fill, source tag and wording.

Implementation guidelines

For developers and AI coding agents (including Google AI Studio). Treat this file as the design source of truth: read the CSS first, then reuse its classes and tokens. Don't re-derive the look from the rendered page.

How to use this file

  1. Copy the CSS in the <style> element, sections 1 TOKENS to 4 LAYOUT, into your app's global stylesheet. Leave out section 5 (.ds-*, documentation only).
  2. Load IBM Plex Sans (400, 500, 600, 700) and IBM Plex Mono (400, 500, 600). Fallback stacks are already in the tokens.
  3. Install lucide (or lucide-react) and use the icon names in §06. Copy the four priority glyph shapes from the sprite (#g-red, #g-orange, #g-yellow, #g-green) and the brand mark (#mf-mark).
  4. Build screens by composing the .mf-* classes from §07. State and meaning are attributes: data-level, data-source, data-state, aria-*.
  5. Use the §09 script as a behaviour reference only: the scoring function, queue banding and override flow. Re-implement them in your framework and keep the logic in one pure, tested utility.

Rules for AI coding agents

  • Never hard-code a colour, size, radius, shadow or duration. Use a --mf-* token. If one is missing, add it to the token block first.
  • Never use red, orange or yellow outside the triage classes and alerts. Never use violet for anything except AI-generated content.
  • Never show a classification without its label and glyph. Never change thresholds, names or targets.
  • Never let AI output set a score, class, rail or ordering. AI may only add the warning ring, the AI tag and text for review.
  • Always tag the source of clinical content with .mf-src and a matching panel rule.
  • Always keep the original complaint visible and unedited.
  • Never use emoji as icons, a second icon library, glassmorphism, large gradients or decorative charts.
  • Do not add diagnoses, treatment advice, statistics, partner logos, pediatric scoring, billing or record-keeping features.

Reference scoring function adult TEWS, exactly as supplied. Needs clinical verification before real use.

function scoreTEWS({ mob, rr, hr, sbp, temp, avpu, trauma }) {
  // Returns null until EVERY input is present. Never a partial or silent score.
  if ([mob, rr, hr, sbp, temp, avpu, trauma].some(v => v === null || v === undefined || Number.isNaN(v))) return null;

  const rrPts   = (rr < 9 || rr > 29) ? 3 : rr >= 21 ? 2 : rr >= 15 ? 1 : 0;                 // 9–14:0 · 15–20:1 · 21–29:2 · <9 or >29:3
  const hrPts   = (hr < 41 || hr > 129) ? 3 : hr >= 111 ? 2 : (hr >= 101 || hr <= 50) ? 1 : 0; // 51–100:0 · 41–50 or 101–110:1 · 111–129:2 · <41 or >129:3
  const sbpPts  = (sbp < 71 || sbp > 199) ? 3 : sbp <= 80 ? 2 : sbp <= 100 ? 1 : 0;           // 101–199:0 · 81–100:1 · 71–80:2 · <71 or >199:3
  const tempPts = (temp < 35.0 || temp > 38.4) ? 1 : 0;                                       // 35.0–38.4:0 · otherwise 1
  const total = mob + rrPts + hrPts + sbpPts + tempPts + avpu + (trauma ? 1 : 0);          // mob 0/1/2 · avpu 0/1/2/3

  const level = total >= 7 ? "red" : total >= 5 ? "orange" : total >= 3 ? "yellow" : "green";
  return { total, level };
}

Open decisions to settle outside the design

  • Firestore collection name. The specification mentions both intake_queue and patients. Nothing in the design depends on either; reconcile in the data layer.
  • Clinical verification of the supplied adult scoring table and time targets before any real-world use.
  • Patients outside adult scope. No pediatric model is defined, so none is designed. Decide how the product should treat such patients (for example, require manual priority) with the clinical lead; the UI must not guess.
  • Queue attention order (Red → AI warnings → awaiting → triaged) is a design proposal and should be confirmed by nurses.
  • Implausible-value thresholds for the "Check this value" prompt, patient-facing safety line, gender options, and the "Other clinical reason" override option need product and clinical approval.
  • Dark theme is deliberately not shipped until every clinical colour pair is re-tested.
